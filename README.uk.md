# linkedin-member-analytics

[English](README.md) · **Українська**

Статистика **вашого особистого профілю LinkedIn** щодня через офіційний API: підсумки за тиждень і знімок
кожного поста після першої доби та після тижня. Результат пишеться в CSV або Google Sheets.

Багато хто (і я донедавна) вважає, що статистику особистого профілю через API не взяти. Можна:
у Community Management API з 2025 року є аналітика учасника. Доступ дають після перевірки, і кілька речей
працюють не так, як у документації. Нижче і те, й інше.

## Що робить

| Команда | Результат |
|---|---|
| `run` | спершу пости, потім тижні; це викликає щоденний cron |
| `posts` | для кожного поста зі списку: рядок через 2 дні і рядок через 7 днів |
| `weeks` | рядок на тиждень пн-нд, добирає історію від `LI_SINCE` |
| `refresh` | новий access-токен із refresh-токена, записує дати кінця обох |
| `probe` | один запит: покази за останні 7 днів |

По посту: покази, охоплені люди, реакції, коментарі, репости, збереження, пересилання, кліки по лінку,
**перегляди профілю з поста, підписники з поста**. Необов'язкові мітки (`rubric`, `format`, `hook`) копіюються
зі списку постів, тож можна порівнювати медіани за типом поста.

За тиждень: ті самі підсумки (без двох метрик, які працюють лише по посту, див. нижче), нові підписники, підписників усього.

## Публікація

`publishing/` містить воркфлоу n8n, який публікує пости, що їх міряє цей інструмент: черга в Google Sheets, схвалення одним натисканням у Telegram, API LinkedIn. Див. [publishing/README.uk.md](publishing/README.uk.md).

## Як я перевірив цифри, перш ніж їм вірити

Нове джерело даних помиляється, доки не збіглося з числом, яке ви вже знаєте.

- На скріні панелі за 14 днів було **938 показів**, скрін зроблено о 13:35 останнього дня.
  API за ті самі 13 повних днів дав **908**; останній день на скріні був неповний (~30 на той момент). Те саме число.
- Панель показала **-54%** до попередніх 14 днів. API показує те саме падіння.
- Старий пост, що «вистрілив» (близько 19 000 показів руками), в API видно як тиждень на 21 000.

## Що не збігається з документацією (жовтень 2026)

- `FOLLOWER_GAINED_FROM_CONTENT` і `PROFILE_VIEW_FROM_CONTENT` задокументовані для обох режимів,
  але `q=me` дає **500 на будь-якому періоді**. По посту (`q=entity`) працюють. У тижнях замість них
  підписники з `memberFollowersCount`.
- Token Generator видає ще й **refresh-токен** (~365 днів), тож access-токен може оновлюватися сам.
- Access і refresh виглядають однаково (обидва починаються з `AQ`, однакова довжина). Скопіюєте refresh
  замість access, і отримаєте `401 INVALID_ACCESS_TOKEN` на всіх запитах.
- Нема ендпоінтів для загальних переглядів профілю, появи в пошуку, частки «поза мережею» і демографії
  аудиторії. Це лишається на щомісячному скріні.
- Кінець `dateRange` не включається. «Останні N днів» у панелі включають сьогодні, тому для старших вікон API
  трохи більший, коли день уже закінчився.

## Як отримати доступ (що спрацювало без зареєстрованої компанії)

1. **Сторінка компанії** в LinkedIn, де ви адмін (вистачить сторінки своєї практики з однієї людини).
2. **Робоча пошта на своєму домені.** Безкоштовно: Cloudflare Email Routing з пересиланням на вашу скриньку.
3. **Сторінка privacy policy** на сайті.
4. **Новий застосунок** у Developer Portal **лише** з Community Management API. Якщо доданий будь-який інший продукт,
   кнопка запиту лишається сірою. У назві без «Linked» і «In».
5. **Settings → verify** застосунку через вашу сторінку компанії.
6. **Products → Community Management API → Request access**, заповнити форму. Опишіть реальне використання:
   лише читання статистики власних постів, один учасник, без даних інших людей.
7. Чекати. Статус «Access Form Review»; мені схвалили через **14 робочих днів** (Development Tier).
8. Вкладка **Auth**: додати redirect URL `https://www.linkedin.com/developers/tools/oauth/redirect`.
   Далі **OAuth Token Generator**: ваш застосунок, `r_member_postAnalytics` і `r_member_profileAnalytics`,
   скопіювати access-токен і refresh-токен.

Ліміт Development Tier: 100 запитів на учасника на добу. Інструмент рахує свої запити і зупиняється на
`LI_DAILY_CAP` (90 за замовчуванням); наступний запуск продовжує з місця зупинки.

## Налаштування

```bash
pip install -r requirements.txt        # потрібно лише для OUTPUT=sheets
cp .env.example .env                   # client id і secret з вкладки Auth
mkdir -p state && umask 077
# вставити токени так, щоб вони не лишились в історії терміналу чи в чаті:
read -r T && printf %s "$T" > state/token     # access-токен
read -r T && printf %s "$T" > state/refresh   # refresh-токен
python -m li_analytics refresh         # доводить, що оновлення працює, записує дати кінця
python -m li_analytics probe
cp posts.example.csv posts.csv         # ваші пости: id, posted_on, post_url, мітки за бажанням
python -m li_analytics run
```

У `post_url` потрібен URN `share` або `ugcPost`, той, що повертає API публікації
(`https://www.linkedin.com/feed/update/urn:li:share:...`). Лінк `urn:li:activity`, скопійований з браузера,
ендпоінт статистики не приймає.

Щоденний cron і монітор, що б'є тривогу, коли `state/last_ok` старший за 3 дні
(він пишеться лише після повністю успішного `run`):

```cron
30 6 * * * cd /path/to/linkedin-member-analytics && python3 -m li_analytics run >> run.log 2>&1
```

## Рішення в коді

- **Порожня відповідь = порожня клітинка, ніколи не 0.** Фальшивий нуль виглядає як поганий тиждень і ховає зламаний запит.
- **Один повтор на 500, далі гучна помилка.** Знята версія API (426) одразу переходить на старшу.
- **Денна стеля = пауза, а не збій.** Рядки, зібрані до стелі, зберігаються.
- **Знімок чекає, доки його вікно закриється**, тож рядок «7 днів» завжди означає 7 повних днів.
- Токени лежать у файлах з правами `0600`; нічого секретного не йде в лог чи вивід.

## Тести

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Тести працюють з фальшивим LinkedIn і вигаданими даними. Кожен перевірено на навмисно зламаній копії коду
(порожня відповідь стає 0, повтор на знятій версії, знімок до закриття вікна, тижневий запит метрик,
що працюють лише по посту): кожна поломка дає червоний тест.
